# v1.4.10 Option Abort Execution

## Goal

After `v1.4.9`, matching was no longer the main bottleneck.

The next question became:

```text
Should target-side prior execution stay open-loop,
or should it abort when the expected structural state stops matching?
```

This version upgrades prior execution from:

```text
open-loop short trace
```

to:

```text
bounded option execution with mismatch abort
```

## Mechanism

Each selected prior now carries:

- `action_trace`
- `signature_trace`

Execution behavior:

1. start a short prior;
2. after each prior-controlled step, compare the observed next signature against
   the expected next signature;
3. if the structure no longer matches, abort the remaining prior steps.

New diagnostics:

- `target_reuse_aborted_prior_count`
- `target_reuse_aborted_prior_steps`

These tell us whether the option-style executor is actually filtering bad
continuations.

## Primary Result

Primary transfer remains unchanged:

```text
final_score = 0
adaptation_auc = 0
```

So again, this is not a success breakthrough.

## Main Comparison

The interesting result is structural, not final.

Abort usually causes:

- more matched priors;
- more prior executions;
- fewer total executed prior steps;
- nonzero aborted counts and aborted steps.

That means the executor is behaving like a filter rather than like a longer
trace player.

## Interpretation

This is not a simple win-or-lose result.

The correct reading is:

```text
abort execution makes reuse more selective
```

What changed consistently:

- matched counts went up;
- executed counts went up;
- executed step totals went down;
- aborted counts became large and meaningful.

This means the new executor is actually cutting prior execution short when the
local structure drifts.

### What Looks Better With Abort

- `operate_replay` on `N2-S4`:
  - better executed transitions;
  - slightly better mobility;
- `motif_fast` on `N4-S5`:
  - better subgoal score;
  - better transitions;
  - better mobility;
- `subgoal_ecology` on `N4-S5`:
  - better subgoal score;
  - better transitions;
  - better mobility.

### What Looks Worse With Abort

- `motif_fast` on `N2-S4`:
  - fewer executed steps;
  - lower executed transition count;
- `subgoal_ecology` on `N2-S4`:
  - fewer executed steps;
  - lower mobility;
- `operate_replay` on `N4-S5`:
  - slightly lower executed subgoal and mobility than open-loop.

## Conclusion

The current best conclusion is:

```text
abort execution is a useful filter,
but not yet a universal replacement for open-loop execution
```

So this version does **not** justify globally promoting abort as the new
default.

It does justify something narrower:

```text
option-style abort is a meaningful branch
and should be kept for the next execution-semantics stage
```

## Recommended Next Step

The next step should not be "abort everywhere."

It should be one of these:

1. compare open-loop vs abort only on the two most promising branches:
   - `cyclic_motif_fast_replay`
   - `cyclic_subgoal_ecology_replay`
2. add mismatch tolerance instead of hard abort:

   ```text
   allow 1 mismatch before abort
   or
   abort only after consecutive mismatches
   ```

3. add a short option policy:

   ```text
   start prior
   continue only while structure stays compatible
   and stop immediately if target-side evidence weakens
   ```

The key lesson from this version is:

```text
execution semantics matter,
and the right semantics are likely method-dependent
```
