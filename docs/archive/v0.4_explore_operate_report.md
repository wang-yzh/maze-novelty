## 1. 摘要

本轮实验测试了一版新的周期结构：

```text
探索 -> 运营 -> 探索 -> 运营 -> 重放
explore -> operate -> explore -> operate -> replay
```

这版设计放弃了把 replay 放进每个大周期的路线。上一轮 `cyclic_replay`
和 `cyclic_three_phase` 显示 replay 能提高可复现性，但会明显拖慢成功路径，
并且容易把方法推向普通强化学习 replay buffer。因此本轮将 replay 降频：
先通过两组“探索-运营”产生并压缩候选行为，再在大周期末尾集中重放成功轨迹。

本轮 MiniGrid-FourRooms-v0 三种随机种子测试中，新方法
`cyclic_operate_replay` 在平均分数上略高于原 `cyclic_novelty`：

| 方法 | 测试成功率 | 成功平均步数 | 测试分数 | 非零成功 seeds |
| --- | ---: | ---: | ---: | ---: |
| `cyclic_operate_replay` | `0.1667 +/- 0.0000` | `10.0000 +/- 2.9439` | `0.3799 +/- 0.0034` | `3/3` |
| `cyclic_novelty` | `0.1667 +/- 0.0000` | `12.6667 +/- 6.2361` | `0.3768 +/- 0.0073` | `3/3` |
| `map_elites_lite` | `0.1667 +/- 0.0000` | `26.3333 +/- 7.1336` | `0.3608 +/- 0.0083` | `3/3` |
| `genetic_q_strong` | `0.1111 +/- 0.1571` | `173.3333 +/- 116.9083` | `0.1580 +/- 0.2234` | `1/3` |
| `go_explore_lite` | `0.0556 +/- 0.0786` | `172.6667 +/- 117.8511` | `0.1282 +/- 0.1813` | `1/3` |
| `q_learning_strong` | `0.0000 +/- 0.0000` | `256.0000 +/- 0.0000` | `0.0000 +/- 0.0000` | `0/3` |

实际情况是：这不是大规模统计证明，但也不是一个随便的 toy positive。
在标准 MiniGrid 环境、增强传统 tabular baselines、加入 Go-Explore lite 和
MAP-Elites lite 竞争后，新周期仍然排名第一，并且主要优势不是更高成功率，
而是同等成功率下更短的成功步数。

## 4. MiniGrid 观测与策略表示

当前所有方法都使用同一个轻量 tabular 观测接口，不使用神经网络。

MiniGrid 原始局部观测为 `7x7x3` 图像，本项目把它压缩为离散特征：

```text
agent direction
front object type
left object type
right object type
seen goal
seen key
seen door
seen lava
carrying object flag
```

状态数量：

```text
4 * 11 * 11 * 11 * 2 * 2 * 2 * 2 * 2 = 85184
```

动作空间被压缩为：

```text
left, right, forward
```

当前没有使用 pickup、drop、toggle 等动作，因为 FourRooms 不需要钥匙或门交互。

策略模型：

```text
tabular Q-table: n_states x n_actions
alpha = 0.25
gamma = 0.96
```

基础环境 reward：

```text
MiniGrid reward - 0.005 step penalty
```

这个设置非常轻。优点是依赖少、可解释、适合快速实验；缺点是观测压缩粗糙，
不能代表完整强化学习模型的能力。

## 5. 统一评分标准

所有方法最终都用相同测试分数比较：

```text
speed = 1 - min(avg_steps, max_steps) / max_steps

test_score =
    0.55 * success_rate
  + 0.30 * speed
  + 0.15 * stability
```

在 MiniGrid 当前实现中，`stability = 0.0`，所以本轮实际比较主要由：

```text
success_rate 和 speed
```

决定。

解释：

- `success_rate`：测试 episode 中成功到达目标的比例。
- `avg_steps`：成功 episode 的平均步数；无成功时记为 `max_steps = 256`。
- `speed`：成功越快越高。
- `test_score`：成功优先，但速度有明确权重。

这个评分符合当前核心假设：最终目标不是“探索得多”，而是“快且正确”。

## 6. 我们的新方法：`cyclic_operate_replay`

周期结构：

```text
explore_a -> operate_a -> explore_b -> operate_b -> replay
```

每个 phase 长度：

```text
phase_len = 4 generations
```

### 6.1 Explore phase

目标：

- 扩大行为多样性。
- 通过 novelty bonus 鼓励到达少访问位置。
- 允许较高随机探索。
- 收集成功轨迹，但不立即强行 replay。

参数：

```text
epsilon = 0.40
novelty_weight = 0.035
mutation_scale = 0.11
mutation_rate = 0.11
```

探索阶段评分：

```text
hidden_score =
    0.30 * success_rate
  + 0.25 * speed
  + 0.25 * trajectory_novelty
  + 0.20 * stability
```

### 6.2 Operate phase

这里的“运营”不是 replay，而是把探索中出现的候选行为压缩成更快、更稳定的策略。

目标：

- 提升成功率。
- 压缩成功步数。
- 更新 hall-of-fame。
- 用低 mutation 保留已经出现的有效策略结构。

参数：

```text
epsilon = max(0.05, 0.24 * (1 - generation / generations))
episodes_per_agent = base + 4
mutation_scale = 0.025
mutation_rate = 0.04
```

运营阶段评分：

```text
success_gate = success_rate^2

exploitation_score =
    0.62 * success_gate
  + 0.28 * speed
  + 0.10 * stability
```

### 6.3 Replay phase

Replay 只在大周期末尾出现。

目标：

- 复现已经成功的轨迹。
- 把成功轨迹写回 tabular Q policy。
- 不让 replay 主导每个周期。

参数：

```text
replay_bank max_items = 160
reinforce passes = 8
replay reward = 0.10
elite_frac = 0.35
mutation_scale = 0.02
mutation_rate = 0.03
```

Replay 阶段评分：

```text
score =
    0.70 * success_rate
  + 0.20 * test_score
  + 0.10 * speed
```

这个设计的关键点是：replay 不再是每轮都出现的训练机制，而是周期末端的“复现检查和记忆巩固”。

## 7. 竞争对手设计

本轮竞争对手不是最强深度强化学习，也不是完整大规模 Go-Explore 或完整 QD 框架。
目标是构造一组轻量、可解释、能在当前机器上跑完的对照。

### 7.1 `q_learning_strong`

普通 tabular Q-learning 的增强版。

增强点：

```text
episode_multiplier = 4
epsilon starts at 0.45 and decays to 0.05
```

意义：

- 检查是否只是因为 Q-learning 训练 budget 太少。
- 给传统强化学习 baseline 更多训练机会。

结果：

```text
0/3 seeds nonzero success
average test_score = 0.0000
```

### 7.2 `genetic_q_strong`

遗传 Q-table baseline 的增强版。

机制：

- population Q-tables。
- 每代训练每个个体。
- 按测试分数选择 elite。
- crossover + mutation 生成下一代。

增强点：

```text
episode_multiplier = 2
eval_count = 10
elite_frac = 0.30
mutation_scale = 0.05
mutation_rate = 0.05
```

结果：

```text
1/3 seeds nonzero success
average test_score = 0.1580
```

注意：seed 7 上 `genetic_q_strong` 是单 seed 最佳，说明它不是无效 baseline。

### 7.3 `cyclic_novelty`

上一阶段表现最稳的原始周期 novelty 方法。

结构：

```text
novelty phase -> exploit phase
```

特点：

- 不使用 replay bank。
- 使用 novelty archive 和 hall-of-fame。
- 是本轮新方法最直接的内部对照。

结果：

```text
3/3 seeds nonzero success
average test_score = 0.3768
average successful steps = 12.6667
```

### 7.4 `go_explore_lite`

来源：Go-Explore。

原始 Go-Explore 论文：

```text
Adrien Ecoffet, Joost Huizinga, Joel Lehman, Kenneth O. Stanley, Jeff Clune.
"Go-Explore: a New Approach for Hard-Exploration Problems."
arXiv:1901.10995.
https://arxiv.org/abs/1901.10995
```

原始算法核心思想：

- 记住之前到达过的状态。
- 先返回一个有希望的状态。
- 再从该状态继续探索。
- 之后通过 imitation learning 等方法 robustify。

本项目实现的是轻量版，不是完整 Go-Explore：

```text
archive: final position -> best action trace
selection: score-weighted cell sampling
return: replay stored action sequence
explore: append random actions
update: if trajectory improves a cell, replace it
robustification: successful traces are distilled into a small Q-table
```

结果：

```text
1/3 seeds nonzero success
average test_score = 0.1282
```

解释：

- 当前 lite 版 Go-Explore 明显弱于完整 Go-Explore。
- 主要弱点是 robustification 太轻，open-loop action trace 在不同 evaluation seeds 上泛化差。
- 但它是合理的轻量竞争对手，因为它实现了“记住 cell、返回、继续探索”的核心骨架。

### 7.5 `map_elites_lite`

来源：Quality-Diversity / MAP-Elites。

原始 MAP-Elites 论文：

```text
Jean-Baptiste Mouret, Jeff Clune.
"Illuminating search spaces by mapping elites."
arXiv:1504.04909.
https://arxiv.org/abs/1504.04909
```

MAP-Elites 核心思想：

- 用户定义行为描述维度。
- 每个行为 cell 保存一个当前最高质量 elite。
- 最终得到的不是单个最优解，而是一张高质量、多样化解的地图。

相关轻量 QD 库：

```text
pyribs
https://pyribs.org/
```

pyribs 是成熟的 Python Quality-Diversity 优化库，包含 archives、emitters、
optimizers 等组件。本轮没有引入 pyribs，原因是当前项目依赖要尽量少，并且我们的
Q-table 离散策略更容易直接内部实现一个 MAP-Elites baseline。

本项目实现：

```text
descriptor = (final_row_bin, final_col_bin, speed_bin)
archive cell = best QAgent for descriptor
candidate generation = sample elite -> mutate -> train -> evaluate
replacement = replace cell only if score improves
```

结果：

```text
3/3 seeds nonzero success
average test_score = 0.3608
average successful steps = 26.3333
```

解释：

- `map_elites_lite` 是本轮最值得重视的外部思想竞争对手。
- 它和我们的周期方法一样能在 3/3 seeds 上成功。
- 它的问题是路径明显更慢。
- 这说明 QD 路线可能很强，但当前轻量 MAP-Elites 在“快且正确”评分下不占优。

## 9. 结果解释

### 9.1 最重要现象

`cyclic_operate_replay` 与 `cyclic_novelty` 的成功率相同，都是 `3/3`
seeds 非零成功，平均成功率都是 `0.1667`。

区别在速度：

```text
cyclic_operate_replay avg_steps = 10.0000
cyclic_novelty        avg_steps = 12.6667
```

因此新周期的优势不是“找到更多成功”，而是在不降低成功稳定性的情况下，
成功路径略短。

这正好对应最初设计目标：

```text
探索可以慢，但最后要快且正确。
```

### 9.2 为什么这次结果值得重视

本轮不是只和弱 Q-learning 比。

对照组包括：

- 强化版 Q-learning。
- 强化版 Genetic Q。
- 上一轮最强内部方法 `cyclic_novelty`。
- Go-Explore 思想的轻量 baseline。
- Quality-Diversity / MAP-Elites 思想的轻量 baseline。

在这个组合下，新周期仍然平均排名第一。这说明它至少不是一个只吃弱 baseline
红利的方案。

### 9.3 最强外部竞争者是 MAP-Elites lite

`map_elites_lite` 达到了：

```text
3/3 seeds nonzero success
test_score = 0.3608
```

它输在速度，不是输在完全找不到目标。这说明 QD 路线与我们的周期路线有真实竞争关系，
后续应该认真比较，而不是把它当作弱 baseline。

### 9.4 Go-Explore lite 当前偏弱

`go_explore_lite` 当前只有：

```text
1/3 seeds nonzero success
test_score = 0.1282
```

原因很可能不是 Go-Explore 思想弱，而是我们的 lite 实现太轻：

- action trace 是 open-loop，换 evaluation seed 后容易失效；
- robustification 只是 tabular trace distillation；
- 没有完整 imitation learning；
- cell representation 只是位置，不含更丰富状态。

因此不能据此说 Go-Explore 弱，只能说本项目的轻量 Go-Explore baseline 当前没有打过周期方法。

## 10. 必须披露的限制

1. 样本数仍然小。

当前只有 3 个 seeds。结果有方向意义，但不足以作为统计证明。

2. MiniGrid 观测压缩很粗。

当前把 `7x7x3` 局部图像压缩成少量离散特征。这可能偏向或限制某些方法。

3. 所有方法都是 tabular。

这不是深度 RL benchmark。没有 PPO、DQN、R2D2、Dreamer 等强现代 RL baseline。

4. Go-Explore 和 MAP-Elites 是 lite 版。

本轮没有运行完整 Go-Explore，也没有引入 pyribs/QDax 等完整 QD 框架。

5. Archive coverage 在 MiniGrid 中解释性较弱。

当前 coverage 使用位置访问计数，但 MiniGrid wrapper 的空间度量还不够精细。
目前应主要看 `test_success`、`avg_steps`、`test_score`。

6. 任务仍然相对简单。

FourRooms 是标准导航环境，但还不是高难度 benchmark。下一步可考虑 DoorKey、
LavaCrossing 或更好的部分可观测特征。

## 11. 初步结论

实际情况如下：

1. 新周期 `explore -> operate -> explore -> operate -> replay` 在本轮 MiniGrid
   对照中排名第一。
2. 它没有靠提高 replay 频率取胜，反而是通过降低 replay 频率后保持成功率、
   改善速度。
3. 与 `cyclic_novelty` 相比，新方法的提升不大，但方向准确：
   `test_score` 从 `0.3768` 到 `0.3799`，成功步数从 `12.6667` 到 `10.0000`。
4. `map_elites_lite` 是当前最值得认真对待的外部竞争对手。
5. `go_explore_lite` 当前结果弱，但不能代表完整 Go-Explore。
6. 这个结果足以支持继续研究“探索-运营-延迟重放”的周期结构。

一句话概括：

```text
这不是最终证明，但它已经是一个值得认真评估的早期算法信号。
```

## 12. 建议下一步

优先级从高到低：

1. 改进 MiniGrid 观测特征。

当前观测太粗。建议加入：

- 更好的目标相对方位；
- 可见空地/墙体结构；
- 局部拓扑签名；
- 上一步动作；
- 短期位置变化。

2. 扩大 seeds。

建议下一轮：

```text
5 seeds or 10 seeds
generations = 30
population = 10
eval_episodes = 8
```

3. 做 ablation。

必须拆开验证：

- 去掉第二组 explore-operate；
- replay 每周期一次 vs 五阶段末尾一次；
- replay passes 变化；
- operate 阶段是否必须使用 success-gated score；
- hall-of-fame 大小变化。

4. 强化 Go-Explore lite。

如果要认真比较，Go-Explore lite 至少需要：

- 更丰富 cell descriptor；
- stochastic evaluation 下的 robust policy；
- 不只依赖 open-loop action trace；
