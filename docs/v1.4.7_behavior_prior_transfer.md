# v1.4.7 Behavior Prior Transfer

## Goal

`v1.4.5-target-reuse-adaptation` established that target-side reuse items could
be extracted from probe rollouts, but simple trace reinforcement was too weak:

```text
items existed
target-side structure existed
final target success remained zero
```

This version tests the next minimal step:

```text
Can target reuse become a temporary behavior prior instead of only a replay trace?
```

The goal is still not to claim target success. The goal is to verify that the
system can move one layer deeper:

```text
extract structure
merge repeated structure
match it back to target-side states
execute it during early adaptation
```

## Mechanism Change

The previous target-reuse item was:

```text
states + actions + score
```

This version upgrades that path into a behavior-prior scaffold.

Added:

- `StateSignature` in `src/minigrid_encoders.py`;
- rollout-side storage of per-step state signatures;
- `BehaviorPrior` and `BehaviorLibrary` in `src/core/behavior.py`;
- navigation-motif-to-prior extraction in `src/transfer/evaluator.py`;
- early adaptation prior execution in addition to the older reinforce path;
- execution diagnostics for matched priors, executed priors, and executed steps.

The new transfer idea is:

```text
target probe rollout
-> extract short navigation priors
-> merge repeated priors by structure
-> early adaptation:
     reinforce selected priors
     and sometimes execute a matched short prior
```

This is still intentionally minimal. It is not yet a full options framework.
The priors are short, open-loop action traces anchored to structural state
signatures.

## New Diagnostic Fields

The transfer diagnostic runner now records:

- `target_reuse_avg_prior_support`
- `target_reuse_best_prior_support`
- `target_reuse_matched_prior_count`
- `target_reuse_executed_prior_count`
- `target_reuse_executed_prior_steps`
- `target_reuse_executed_episode_count`
- `target_reuse_idle_episode_count`
- `target_reuse_executed_episode_avg_subgoal_score`
- `target_reuse_executed_episode_avg_region_transitions`
- `target_reuse_executed_episode_avg_mobility`
- `target_reuse_idle_episode_avg_subgoal_score`
- `target_reuse_idle_episode_avg_region_transitions`
- `target_reuse_idle_episode_avg_mobility`

Interpretation:

- support asks whether a prior is a repeated structural fragment rather than a
  one-off trace;
- matched count asks whether the current target-side behavior ever revisits a
  compatible structural situation;
- executed count and executed steps ask whether the behavior-prior path is
  actually active during adaptation.
- executed-vs-idle episode metrics ask whether prior-triggered episodes carry
  stronger structural movement than episodes where the prior path stays idle.

These fields do not prove transfer quality by themselves. They only answer the
previously missing mechanism question:

```text
Did the new prior executor really fire?
```

## Quick Probe

This first probe keeps the budget intentionally small.

Command:

```bash
uv run python scripts/run_pretraining_transfer_diagnostic.py \
  --seeds 7 \
  --target-envs MiniGrid-MultiRoom-N2-S4-v0,MiniGrid-MultiRoom-N4-S5-v0 \
  --pretrain-episodes 20 \
  --adapt-episodes 20 \
  --eval-every 10 \
  --eval-episodes 3 \
  --include-target-reuse \
  --output outputs/pretraining_behavior_prior_probe.csv \
  --summary-output outputs/pretraining_behavior_prior_probe_summary.csv
```

This is not a benchmark claim. It is a mechanism probe.

## Interpretation

This version does not yet solve transfer. It does prove something more specific
than `v1.4.5` proved.

We now know:

1. target-side trace reuse can be upgraded into a structural behavior-prior
   library;
2. those priors can be merged, so repeated fragments survive as higher-support
   items rather than remaining raw duplicate traces;
3. those priors are matched hundreds of times during early adaptation on both
   tested targets;
4. those priors are actually executed, often for hundreds of steps across the
   short adaptation budget;
5. therefore the new bottleneck is no longer "is the executor dead?" but
   "why does frequent prior execution still fail to create task success?"
6. executed-prior episodes already separate into different structural profiles:
   `operate_replay` tends to produce the highest room-transition counts on
   `N4-S5`, `cyclic_subgoal_ecology_replay` tends to produce the highest
   executed-episode subgoal score, and `cyclic_motif_fast_replay` shows the
   strongest repeated-prior evidence.

The most interesting small positive signal in this quick probe is:

```text
cyclic_motif_fast_replay_pretrain + target reuse
produced the strongest repeated-prior evidence
best support = 8 on N4-S5
```

Two other useful small signals also appear:

```text
operate_replay_pretrain + target reuse:
  strongest executed-episode region transitions on N4-S5

cyclic_subgoal_ecology_replay_pretrain + target reuse:
  strongest executed-episode subgoal score on both tested targets
```

That suggests the artifact families may already be splitting into different
roles:

- `motif_fast`: most repeated short fragments;
- `operate_replay`: strongest transition-driving prior execution;
- `subgoal_ecology`: strongest progress-oriented prior execution.

## Decision Rule

Do not promote this version because of item count alone.

Promote it only if a larger follow-up run improves at least one of:

- `target_probe_region_transitions` after adaptation-side reuse is instrumented
  more directly;
- `adaptation_auc`;
- `time_to_first_success`;
- `final_score_under_budget`.

Retain the scaffold if:

- repeated priors continue to appear;
- matched and executed counts remain substantial across seeds;
- the next run can show that executed priors improve target-side structure even
  before task success appears.

## Next Step

The next step should stay narrow.

Do:

1. run a 3-seed follow-up with the same mechanism;
2. add adaptation-side diagnostic deltas, especially mobility and region
   transitions during prior-triggered episodes;
3. compare which artifact family produces the best repeated, executable priors
   and which produces the strongest executed-episode structure.

Do not:

- add another large cycle variant;
- increase the action set yet;
- declare a transfer breakthrough from this version.

## Short Thesis

`v1.4.5` showed:

```text
target reuse items exist
```

This version shows:

```text
target reuse items can become executable structural priors
and they do fire during adaptation
```

The transfer problem is still unsolved. The mechanism is no longer purely
conceptual.
