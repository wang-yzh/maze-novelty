# v1.4.20 Prior-Kind Lifecycle Diagnostics

## Purpose

`v1.4.19` showed that `kind_structural_guard` is not ready to promote. It can
recover some structural quality on `N4-S5`, but it regresses badly on `N2-S4`.

The next question is no longer:

```text
Which continuation guard should we tune next?
```

The better question is:

```text
Which behavior-prior kind is actually failing, and how?
```

This version adds lifecycle diagnostics by `BehaviorPrior.kind`. It does not
change behavior-prior selection, execution, abort logic, rewards, adaptation, or
training behavior.

## Code Changes

Added `PriorKindStats` in `src/transfer/evaluator.py`.

Each prior kind now records:

- matched priors;
- started priors;
- completed priors;
- truncated priors;
- aborted priors;
- executed steps;
- aborted steps;
- mismatch, stall, effect mismatch, and structural evidence steps;
- first-step mismatch, stall, effect mismatch, and structural evidence counts;
- abort counts by reason.

`TargetReuseSummary` now includes two compact JSON diagnostics:

```text
target_reuse_item_kind_counts_json
target_reuse_prior_kind_stats_json
```

The CSV output keeps these as JSON fields instead of expanding every kind into
dozens of columns. This keeps the main report readable while preserving the
raw diagnosis for later parsing.

## First Diagnostic Read

### N2-S4

`operate_replay_pretrain` target reuse library:

```text
{"region_transition":1,"unstuck":7}
```

Its execution was permissive and completion-heavy:

```text
region_transition: started 6, completed 6, aborted 0
unstuck: started 61, completed 60, aborted 0
```

This means open-loop reuse is not silent. It starts and completes options, but
those completed options still do not compose into task success.

`cyclic_motif_fast_replay_pretrain` target reuse library:

```text
{"region_transition":4,"unstuck":9}
```

With `kind_structural_guard` patience 4:

```text
region_transition: started 50, completed 1, structural_aborts 47
unstuck: started 57, completed 10, structural_aborts 45
```

This explains the `N2-S4` regression from `v1.4.19`: the guard is not merely
filtering bad continuations. It is killing most motif-fragment execution.

### N4-S5

`cyclic_motif_fast_replay_pretrain` target reuse library:

```text
{"forward_run":2,"region_transition":1,"unstuck":12}
```

Lifecycle:

```text
forward_run: started 23, completed 7, effect_aborts 16
region_transition: started 7, completed 1, structural_aborts 6
unstuck: started 59, completed 18, structural_aborts 39, effect_aborts 2
```

The useful signal is sharper here:

- `forward_run` is mostly failing by effect mismatch;
- `region_transition` is failing by lack of structural evidence;
- `unstuck` starts often, completes sometimes, but is heavily pruned by the
  structural guard.

This is exactly the evidence needed before building semantic prior executors.

`cyclic_subgoal_ecology_replay_pretrain` target reuse library:

```text
{"region_transition":5,"unstuck":6}
```

Lifecycle:

```text
region_transition: started 37, completed 16, progress_lost_aborts 20
unstuck: started 41, completed 25, progress_lost_aborts 16
```

Ecology priors are not failing through effect mismatch. They are failing through
the coarse progress guard. This suggests a different upgrade path than motif
priors.

## Interpretation

The old aggregate diagnostics hid a key distinction:

```text
motif priors fail mainly through effect and structural guards;
ecology priors fail mainly through progress guard loss;
operate open-loop priors complete often but remain semantically weak.
```

That is stronger evidence than another global continuation rule comparison.

## Decision

Keep this as a diagnostic release.

Do not tune `structural_patience` further until we decide which prior kinds
should become semantic executors.

Recommended next version:

```text
v1.5.0 semantic behavior prior prototype
```

Start with three intent-level executors:

1. `forward_run`
2. `region_transition`
3. `unstuck`

Keep `action_trace` as an example trajectory, but let the executor re-plan
locally around the intent.
