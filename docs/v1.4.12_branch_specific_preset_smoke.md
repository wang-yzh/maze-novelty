# v1.4.12 Branch-Specific Preset Smoke

## Goal

After `v1.4.11`, the natural next question was:

```text
Should we stop using one uniform target-reuse execution policy
and switch to branch-specific execution presets?
```

The branch-specific hypothesis was:

- `operate_replay` stays closer to `open_loop`;
- `cyclic_motif_fast_replay` uses `soft_abort`;
- `cyclic_subgoal_ecology_replay` uses `soft_abort`.

This is a narrower question than adding a new algorithm. It is only about how
to wire the current execution semantics to the existing artifact families.

## Implementation

The transfer diagnostic runner now supports:

```text
--reuse-preset-mode uniform
--reuse-preset-mode branch_specific
```

Current branch-specific mapping:

```text
operate_replay_pretrain -> open_loop
cyclic_motif_fast_replay_pretrain -> abort_t1
cyclic_subgoal_ecology_replay_pretrain -> abort_t1
everything else -> current CLI uniform settings
```

This is an experiment-runner feature only. It does not change the artifact or
execution core by itself.

uv run python scripts/run_pretraining_transfer_diagnostic.py \

## Quick Result

The important observation is:

```text
branch-specific does not change motif_fast or subgoal_ecology in this setup
because both already use soft_abort.

The only real difference in this smoke is operate_replay:
uniform -> soft_abort
branch-specific -> open_loop
```

So the smoke is mainly a quick check on whether `operate_replay` should be
carved out as an exception.

### `MiniGrid-MultiRoom-N2-S4-v0`

`operate_replay`:

| Setting | Executed Steps | Aborted Steps | Exec Transitions | Exec Mobility |
| --- | ---: | ---: | ---: | ---: |
| `uniform soft_abort` | `345.0` | `40.0` | `0.0000` | `0.1367` |
| `branch_specific open_loop` | `399.0` | `0.0` | `0.0000` | `0.1230` |

Interpretation:

```text
branch-specific recovers execution length,
but does not improve structural execution metrics.
```

### `MiniGrid-MultiRoom-N4-S5-v0`

`operate_replay`:

| Setting | Executed Steps | Aborted Steps | Exec Subgoal | Exec Transitions | Exec Mobility |
| --- | ---: | ---: | ---: | ---: | ---: |
| `uniform soft_abort` | `222.0` | `89.0` | `0.1267` | `3.7500` | `0.1963` |
| `branch_specific open_loop` | `245.0` | `0.0` | `0.0825` | `2.2500` | `0.1523` |

Interpretation:

```text
branch-specific recovers steps,
but the structural execution signal is clearly worse in this quick smoke.
```

## Conclusion

This is a useful negative result.

It does **not** justify promoting branch-specific execution presets yet.

The best reading is:

```text
the branch-specific idea is plausible in theory,
but this quick smoke does not yet show enough value to replace the current
uniform soft-abort baseline
```

In particular:

- the mapping is too coarse;
- the only differing branch in this smoke (`operate_replay`) does not clearly
  improve under the branch-specific choice;
- the existing 3-seed execution studies are still more informative than this
  quick preset split.

## Decision

Do not launch a full 3-seed branch-specific preset benchmark yet.

Keep the preset logic in the runner because it is useful for future work, but do
not promote it as the new main experimental protocol.

## Next Step

The next better question is not:

```text
which preset should every branch use?
```

It is:

```text
what stronger execution mechanism should each promising branch test next?
```

That means:

- keep `direction_agnostic` as default matching;
- keep uniform `soft_abort` as the current main reusable-execution baseline;
- when needed, compare branch-specific presets only inside a narrower branch
  study, not as the new global experiment harness.
