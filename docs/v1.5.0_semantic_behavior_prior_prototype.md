# v1.5.0 Semantic Behavior Prior Prototype

## Purpose

`v1.4.20` made the bottleneck legible:

```text
motif priors fail mainly through effect and structural guards;
ecology priors fail mainly through progress guard loss;
operate open-loop priors complete often but remain semantically weak.
```

That points away from another global continuation rule and toward a better
prior representation.

This version adds the first semantic behavior-prior executor.

## Main Idea

Old execution:

```text
match state signature
play action_trace
abort if the trace drifts too far
```

New experimental execution:

```text
match state signature
read prior kind as an intent
choose a local action from current geometry
use action_trace as budget and tie-breaker
verify effects through the existing continuation guard
```

The action trace is still stored, but it is no longer the only source of
actions for supported prior kinds.

## New Execution Mode

Added:

```text
semantic_intents
```

CLI usage:

```text
--reuse-execution-mode semantic_intents
```

Supported prior kinds:

| Kind | Semantic action rule |
| --- | --- |
| `forward_run` | move forward when front is passable; otherwise turn toward an open side |
| `region_transition` | move toward visible goal if possible; otherwise move forward or turn toward open side |
| `unstuck` | move forward when possible; otherwise turn toward open side |

Unsupported kinds still fall back to trace execution.

## Important Implementation Details

Semantic execution is opt-in. Existing modes keep their old behavior:

```text
default
motif_fragments
semantic_intents
```

For supported semantic priors, `first_step` effect filtering no longer uses the
stored first trace effect. The trace may be stale because semantic execution can
choose a different first action from the current local geometry.

The expected effect for the chosen semantic action is computed from the current
state signature:

```text
turn_left
turn_right
forward_move if front is passable
forward_blocked otherwise
```

`semantic_intents` also reuses the motif-fragment library fallback path. This
prevents branch-specific runs from going silent when `min_execution_support=2`
is too strict for a small diagnostic budget.

## Interpretation

This is the strongest evidence so far that the expression layer matters.

The semantic executor did not solve the hard target task, but it converted many
guard-killed priors into sustained local behavior:

```text
motif N4-S5: completed 26 -> 94
motif N4-S5: aborted 63 -> 0
motif N4-S5: avg transitions 9.00 -> 16.75
motif N4-S5: avg mobility 0.1738 -> 0.3682
ecology N4-S5: avg transitions 9.25 -> 22.75
ecology N4-S5: avg mobility 0.1582 -> 0.3574
```

The remaining problem is composition:

```text
semantic priors now move around better,
but adaptation still does not turn those movements into solved episodes.
```

## Decision

Keep `semantic_intents` experimental.

Do not promote it as the default transfer executor yet because:

- final score and adaptation AUC are still zero;
- this is one seed and a small smoke budget;
- operate replay regressed on `N4-S5` transition count;
- semantic behavior can over-execute locally useful movement without solving
  the global task.

## Next Step

The next version should add composition diagnostics:

```text
Do semantic priors move the agent closer to a new room, doorway, or goal sighting
within the same episode?
```

Candidate metrics:

- pre-prior and post-prior region id;
- pre-prior and post-prior goal visibility;
- displacement from prior start;
- whether the next few non-prior steps continue progress or collapse;
- per-kind post-execution subgoal delta.

Only after that should we decide whether to make semantic priors affect Q-value
updates differently.
