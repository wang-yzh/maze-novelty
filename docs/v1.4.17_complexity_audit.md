# v1.4.17 Complexity Audit

## Purpose

This document freezes the current complexity picture.

The question is no longer:

```text
Can we add another plausible mechanism?
```

The question is:

```text
Which existing mechanisms have earned their complexity?
```

The answer is mixed:

```text
complexity has bought useful diagnosis,
but it has not yet bought hard transfer performance
```

So the project should stop mechanism expansion and move into controlled
selection.

## Current Bottom Line

The current transfer experiments still show:

```text
final_score = 0
adaptation_auc = 0
```

on the hard MiniGrid transfer smoke runs.

That means no current behavior-prior mechanism can be promoted as a solved
transfer method.

However, recent complexity did expose real bottlenecks:

- target-side priors can be found;
- priors can be executed;
- signature mismatch and movement-effect mismatch are different failures;
- open-loop completion is not proof of useful structure;
- `motif_fast` and `subgoal_ecology` fail in different ways.

That is enough to keep several mechanisms as research tools, but not enough to
keep expanding the system unchecked.

## Classification

### Main Line

These are the mechanisms that should remain central to future experiments.

| Mechanism | Status | Reason |
| --- | --- | --- |
| pretraining-transfer framework | keep as main frame | matches the long-term goal better than direct maze solving |
| `cyclic_operate_replay` / `operate_replay_pretrain` | keep as baseline | clean historical baseline with low conceptual complexity |
| `cyclic_motif_fast_replay_pretrain` | keep as main research branch | represents success-fragment and speed-discipline memory |
| `cyclic_subgoal_ecology_replay_pretrain` | keep as main research branch | represents failure-derived structural memory |
| `direction_agnostic + soft_abort` reuse baseline | keep as comparison baseline | still the least misleading execution baseline |

### Diagnostic Tools

These mechanisms have earned their place because they explain failures.

| Mechanism | Status | Reason |
| --- | --- | --- |
| target probe diagnostics | keep | exposes artifact behavior before target adaptation |
| subgoal / transition / mobility metrics | keep | final score is too silent on sparse tasks |
| prior lifecycle diagnostics | keep | separates launch failure, abort failure, completion, and truncation |
| `effect_trace` metrics | keep | shows signature mismatch is not the same as movement-effect failure |
| branch-specific CSV config recording | keep | prevents misleading experiment records |

### Experimental Mechanisms

These should remain available, but they are not promoted.

| Mechanism | Status | Reason |
| --- | --- | --- |
| branch-specific preset mode | experimental | changes behavior but has not improved primary transfer metrics |
| `motif_fragments` executor | experimental | can change structural execution, but signal is small/inconsistent |
| `motif_consistency` continuation | experimental | stricter and sometimes structurally cleaner, but brittle |
| `progress_guard` continuation | experimental | useful for ecology priors, but progress evidence is too coarse |
| `effect_consistency` continuation | experimental | completes many more motif options, but can reduce structural quality |

### Downgrade / Do Not Optimize Now

These should not receive more tuning until stronger evidence appears.

| Mechanism | Status | Reason |
| --- | --- | --- |
| open-loop prior execution | diagnostic only | completion volume is not useful structure |
| first-step effect matching as a standalone filter | downgrade | produced almost no change because it overlaps with local signatures |
| simple trace reinforcement | downgrade | found structure but did not create success |
| new large ecology cycle variants | stop for now | would increase complexity faster than understanding |
| raw memory volume metrics | downgrade | more motifs/niches does not mean more transferable behavior |

## Complexity ROI

### Performance ROI

Current answer:

```text
not proven
```

Hard transfer final metrics remain zero in the smoke runs.

No recent reuse mechanism has earned mainline promotion by final score,
adaptation AUC, or time-to-first-success.

### Diagnostic ROI

Current answer:

```text
proven
```

The added complexity produced new, actionable distinctions:

- launch failure versus continuation failure;
- signature mismatch versus movement-effect failure;
- completion count versus structural quality;
- success-derived memory versus failure-derived memory.

This is real research value.

### Engineering ROI

Current answer:

```text
acceptable, but near the limit
```

The codebase now has enough hooks to test transfer hypotheses. More mechanism
layers will likely reduce clarity unless tied to a promotion rule.

## Promotion Rules

From this point forward, a mechanism should be promoted only if it passes one
of these gates.

### Primary Promotion

A mechanism can become mainline if, on at least 3 seeds and at least 2 target
tasks, it improves one primary metric without a large regression in the others:

- adaptation AUC;
- time to first success;
- final score;
- transfer lift;
- negative transfer rate.

### Diagnostic Promotion

A mechanism can remain as a diagnostic tool if it reveals a failure mode that
changes the next engineering decision.

Examples:

- first-step signature mismatch;
- effect mismatch;
- progress-lost abort;
- executed versus idle episode structure.

### Demotion

A mechanism should be demoted if:

- it only increases execution volume;
- it only increases memory count;
- it does not alter a bottleneck diagnosis;
- it works only on one quick seed;
- it requires new tuning without explaining why.

## Current Main Experiment Stack

The recommended stack for near-term work is:

```text
source pretraining:
  operate_replay_pretrain
  cyclic_motif_fast_replay_pretrain
  cyclic_subgoal_ecology_replay_pretrain

target reuse baseline:
  direction_agnostic + soft_abort

diagnostics:
  target probes
  prior lifecycle
  effect_trace
  subgoal / transition / mobility

experimental branch:
  effect_consistency
  progress_guard
  motif_fragments
```

Do not add new cycle families until this stack produces either:

```text
nonzero transfer success
```

or:

```text
a clear reason why target-side execution cannot create success yet
```

## Next Work Item

The next useful work item is not another cycle.

It is a hybrid continuation gate:

```text
continue while movement effect matches,
but require periodic structural evidence
```

Candidate structural evidence:

- region transition;
- subgoal progress;
- novelty / new region entry;
- reduced revisiting;
- mobility above a floor.

This would sit between:

```text
signature consistency:
  too brittle

effect consistency:
  too permissive
```

The expected test is not simply "does completion increase?"

The real test is:

```text
can we preserve effect_consistency's completion gain
without losing structural transitions and mobility?
```

## Decision

The project should now follow this rule:

```text
no new macro-cycle variants until complexity is either promoted, demoted,
or explained by the audit categories above
```

This keeps the project aligned with the pretraining goal instead of drifting
back into mechanism sprawl.
