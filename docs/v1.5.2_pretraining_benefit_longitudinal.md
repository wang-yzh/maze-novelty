# v1.5.2 Pretraining Benefit Longitudinal

## Purpose

The project has shown that pretraining changes target-side behavior structure.
It has not yet shown that pretraining improves target-task adaptation.

This version adds a longitudinal benefit validation script. Its job is to ask a
stricter question:

```text
Under the same target task, adaptation budget, executor, and paired seeds,
does a pretrained artifact outperform scratch and negative controls?
```

## New Script

```text
scripts/run_pretraining_benefit_longitudinal.py
```

Outputs:

```text
report csv   -> one row per condition/run
points csv   -> one row per eval step
summary csv  -> grouped means/stds
```

The `points` output is important. A single final score can miss transient
benefits or regressions.

## Conditions

The script compares:

| Condition | Purpose |
| --- | --- |
| `scratch` | target adaptation from scratch |
| `pretrained_agent` | pretrained Q-table only |
| `target_reuse` | pretrained agent plus target-side behavior-prior reuse |
| `shuffled_prior_control` | same target probe, but prior intent/action pairing is scrambled |
| `random_artifact_control` | untrained artifact passed through the same machinery |

The random artifact and shuffled-prior controls are essential. Without them,
region transitions, mobility, or even transient success can be misattributed to
pretraining.

## Paired Seed Correction

During calibration, an important issue appeared: no-reuse and target-reuse runs
were initially using different adaptation/evaluation seeds. That made zero-step
comparisons invalid.

This was corrected before recording the final smoke results. For a given
artifact and target, these conditions now share the same adaptation seed:

```text
pretrained_agent
target_reuse
shuffled_prior_control
```

This makes `eval_step = 0` directly comparable.

## New Evaluator Helper

Added:

```text
evaluate_transfer_with_reuse_items(...)
```

This lets the script evaluate real and shuffled reuse items through the same
adaptation path.

## Hard-Target Smoke

Command:

```text
uv run python scripts/run_pretraining_benefit_longitudinal.py \
  --seeds 7 \
  --target-envs MiniGrid-MultiRoom-N2-S4-v0,MiniGrid-MultiRoom-N4-S5-v0 \
  --methods operate_replay_pretrain,cyclic_motif_fast_replay_pretrain,cyclic_subgoal_ecology_replay_pretrain \
  --pretrain-episodes 16 \
  --adapt-episodes 12 \
  --eval-every 6 \
  --eval-episodes 2 \
  --reuse-probe-episodes 4 \
  --output outputs/pretraining_benefit_longitudinal_quick.csv \
  --points-output outputs/pretraining_benefit_longitudinal_quick_points.csv \
  --summary-output outputs/pretraining_benefit_longitudinal_quick_summary.csv
```

Result:

```text
All final_score = 0
All adaptation_auc = 0
All adaptation_auc_lift = 0
All goal_visibility_gain = 0
```

This means the hard-target smoke gives no task-level evidence that pretraining
improves adaptation.

Structural proxy metrics still differ. For example:

```text
N4-S5 target_reuse cyclic_motif_fast_replay:
  region changes = 56
  goal gains = 0

N4-S5 shuffled_prior_control cyclic_motif_fast_replay:
  region changes = 48
  goal gains = 0

N4-S5 target_reuse random_artifact_control:
  region changes = 15
  goal gains = 0
```

The lesson is that region changes alone are not enough. They can appear in true
reuse, shuffled controls, and random controls without producing task success.

## Same-Source Calibration

Command:

```text
uv run python scripts/run_pretraining_benefit_longitudinal.py \
  --seeds 7 \
  --target-envs MiniGrid-FourRooms-v0 \
  --methods operate_replay_pretrain,cyclic_motif_fast_replay_pretrain,cyclic_subgoal_ecology_replay_pretrain \
  --pretrain-episodes 16 \
  --adapt-episodes 12 \
  --eval-every 6 \
  --eval-episodes 2 \
  --reuse-probe-episodes 4 \
  --output outputs/pretraining_benefit_longitudinal_calibration.csv \
  --points-output outputs/pretraining_benefit_longitudinal_calibration_points.csv \
  --summary-output outputs/pretraining_benefit_longitudinal_calibration_summary.csv
```

Result:

```text
random_artifact_control + target_reuse:
  adaptation_auc = 0.2816
  final_score = 0
  time_to_first_success = 6

all tested pretrained methods:
  adaptation_auc = 0
  final_score = 0
```

This is a useful warning. Target-side reuse can sometimes create a transient
success even without pretraining. Therefore, any future claim of pretraining
benefit must beat both:

```text
random_artifact_control
shuffled_prior_control
```

## Current Answer

The current honest answer is:

```text
We have evidence that pretraining changes target-side behavior structure.
We do not yet have evidence that pretraining improves target-task adaptation.
```

The stronger version:

```text
Some structural proxy improvements are not unique to trained artifacts.
They can also appear in random and shuffled controls.
```

## Decision

Do not claim pretraining benefit yet.

The validation bar is now:

```text
positive adaptation_auc_lift or earlier first success
AND better than random_artifact_control
AND better than shuffled_prior_control
across multiple seeds
```
