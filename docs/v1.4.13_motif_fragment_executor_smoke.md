# v1.4.13 Motif Fragment Executor Smoke

## Goal

`v1.4.12` showed that a coarse branch-specific preset split was not enough.

The next minimal improvement was:

```text
give cyclic_motif_fast_replay a genuinely different executor
instead of only a different preset
```

The implemented idea:

```text
motif_fragments
```

Meaning:

- prefer repeated priors;
- prefer shorter fragments;
- prefer non-fallback motif priors over generic `target_trace` priors;
- but do not go completely silent when the budget is too small for strong
  repeated motifs.

## Mechanism

The new branch-specific executor keeps the same outer reuse pipeline, but
changes which prior is selected for execution:

```text
default:
  score-first prior selection

motif_fragments:
  support-first
  then shorter action trace
  then score
```

It also stages the library filter:

1. non-trace priors with higher support;
2. if empty, relax support;
3. if still empty, finally allow trace priors.

This avoids the "silent executor" failure mode.

## Smoke Command

```bash
uv run python scripts/run_pretraining_transfer_diagnostic.py \
  --seeds 7 \
  --target-envs MiniGrid-MultiRoom-N2-S4-v0,MiniGrid-MultiRoom-N4-S5-v0 \
  --methods operate_replay_pretrain,cyclic_motif_fast_replay_pretrain,cyclic_subgoal_ecology_replay_pretrain \
  --pretrain-episodes 16 \
  --adapt-episodes 12 \
  --eval-every 6 \
  --eval-episodes 2 \
  --include-target-reuse \
  --reuse-preset-mode branch_specific \
  --reuse-match-modes direction_agnostic \
  --reuse-abort-on-mismatch \
  --reuse-mismatch-tolerance 1 \
  --output outputs/pretraining_branch_preset_branch_v5_quick.csv \
  --summary-output outputs/pretraining_branch_preset_branch_v5_quick_summary.csv
```

Baseline for comparison:

```text
uniform soft-abort
```

from `v1.4.11`.

## Quick Result

This smoke does produce a real branch-specific difference now, but only a small
one.

### `MiniGrid-MultiRoom-N2-S4-v0`

`cyclic_motif_fast_replay`:

| Setting | Exec Steps | Aborted Steps | Exec Subgoal | Exec Transitions | Exec Mobility |
| --- | ---: | ---: | ---: | ---: | ---: |
| `uniform soft-abort` | `508.0` | `20.0` | `0.0541` | `2.2500` | `0.1055` |
| `branch-specific motif_fragments` | `498.0` | `27.0` | `0.0550` | `3.2500` | `0.1123` |

Interpretation:

```text
slightly less execution volume,
slightly better structural execution quality
```

This is a real signal, but still a small one.

### `MiniGrid-MultiRoom-N4-S5-v0`

`cyclic_motif_fast_replay`:

| Setting | Exec Steps | Aborted Steps | Exec Subgoal | Exec Transitions | Exec Mobility |
| --- | ---: | ---: | ---: | ---: | ---: |
| `uniform soft-abort` | `415.0` | `116.0` | `0.0804` | `9.0000` | `0.1738` |
| `branch-specific motif_fragments` | `415.0` | `116.0` | `0.0804` | `9.0000` | `0.1738` |

Interpretation:

```text
no meaningful change in this quick smoke
```

### `operate_replay`

Branch-specific still routes this method to open-loop.

That continues to recover executed steps, but does not clearly improve the
structural execution signal in this smoke.

## Conclusion

This is another useful small result:

```text
motif-specific execution can change behavior,
but the current motif_fragments executor is still too weak to justify a full
branch-specific promotion
```

The executor is no longer silent, which is important.

But the signal is still too small and too inconsistent:

- a small positive effect on `N2-S4`;
- essentially no effect on `N4-S5`.

## Decision

Do not promote branch-specific execution presets yet.

Keep:

- the preset support in the runner;
- the `motif_fragments` executor as an experimental branch;
- the uniform `direction_agnostic + soft_abort` setup as the main execution
  baseline.

## Next Step

The next worthwhile upgrade should not be another selection heuristic alone.

The next stronger idea should likely be:

```text
option execution with branch-specific continuation rules
```

For example:

- `motif_fast`: continue while fragment consistency stays high;
- `subgoal_ecology`: continue while progress/subgoal evidence stays alive.

That would be a larger step than the current executor ranking tweak, and is
more likely to produce a meaningful branch-specific difference.
