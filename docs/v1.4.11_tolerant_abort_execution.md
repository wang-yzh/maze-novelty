# v1.4.11 Tolerant Abort Execution

## Goal

`v1.4.10` showed that hard abort is a real execution filter:

- more matched priors;
- more executed priors;
- fewer executed steps;
- large aborted counts.

But hard abort was not a universal improvement. In some settings it clearly
filtered bad continuations; in others it cut too aggressively.

This version asks:

```text
Can we keep the filtering effect while reducing over-pruning?
```

The tested variant is:

```text
soft abort
```

Operationally:

```text
allow 1 consecutive mismatch before abort
```

## Mechanism

New parameter:

```text
mismatch_tolerance
```

Semantics:

- `0` means hard abort on the first mismatch;
- `1` means abort only after the second consecutive mismatch;
- a matching step resets the mismatch counter.

This keeps the option-like execution behavior, but makes it less brittle to one
bad local step.

## Primary Result

Primary transfer is still unchanged:

```text
final_score = 0
adaptation_auc = 0
```

So this is not a task-success breakthrough either.

## Main Reading

Soft abort behaves like a middle point between open-loop and hard abort.

Common pattern:

- more matched priors than open-loop;
- fewer aborted steps than hard abort;
- executed steps often recover part of what hard abort removed.

This means soft abort is doing what it was intended to do:

```text
keep some filtering
without cutting execution as aggressively as hard abort
```

## Conclusion

Soft abort is a real improvement over the simple binary choice:

```text
open-loop
vs
hard abort
```

But it is still not a universal winner.

The most honest summary is:

```text
soft abort is a better compromise setting,
especially where hard abort was obviously over-pruning,
but the best execution policy still appears to be method-dependent
```

## Recommendation

Do not make `soft_abort(tolerance=1)` the universal default yet.

Instead:

1. keep `direction_agnostic` as the default matching rule;
2. narrow future execution experiments to the two most interesting branches:
   - `cyclic_motif_fast_replay`
   - `cyclic_subgoal_ecology_replay`
3. treat soft abort as the better starting point for those branches;
4. for `operate_replay`, continue to compare against open-loop.

The next high-value experiment is now:

```text
branch-specific execution semantics
```

not one global execution rule for every artifact family.
