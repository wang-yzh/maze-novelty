# v1.4.19 Kind-Aware Structural Guard

## Goal

`v1.4.18` showed that a global structural gate was the wrong level of
abstraction.

This step tests:

```text
kind_structural_guard
```

The hypothesis:

```text
different option kinds need different survival evidence
```

## Mechanism

The new rule keeps the effect requirement:

```text
abort immediately if movement effect mismatches
```

Then it checks structural evidence by `prior.kind`.

| Prior Kind | Structural Evidence |
| --- | --- |
| `forward_run` | forward action produces real movement |
| `region_transition` | region changes, goal appears, or displacement from start becomes meaningful |
| `wall_follow_left` / `wall_follow_right` | forward movement after the turn/avoidance behavior |
| `unstuck` | leaves the start neighborhood |
| `target_trace` | no strong structural evidence; should remain diagnostic |

This is narrower than another global patience tweak. It asks:

```text
what does it mean for this specific kind of option to still be alive?
```

## Implementation Notes

Added:

```text
kind_structural_guard
```

to the available continuation rules.

The branch-specific motif preset currently uses:

```text
cyclic_motif_fast_replay_pretrain:
  execution_mode = motif_fragments
  effect_match_mode = first_step
  continuation_rule = kind_structural_guard
```

This is still experimental. It is not a mainline promotion.

## Decision

Do not promote `kind_structural_guard`.

Keep it as an experimental rule and a useful diagnostic result.

The mechanism is directionally better than a global structure gate on `N4-S5`,
but it does not pass the promotion bar:

- no primary transfer improvement;
- no nonzero adaptation score;
- one target improves structurally while another target regresses;
- sensitivity to `structural_patience` is too high.

## What This Teaches Us

The tradeoff is now sharper:

```text
kind-aware evidence is the right abstraction level,
but the project lacks outcome statistics by option kind
```

Right now, `structural_abort_count` is aggregated across all priors. That is not
enough.

We need to know:

```text
which kind is being killed?
which kind completes?
which kind produces transitions?
which kind produces mobility?
```

Without that, further tuning is blind.
