## Interpretation

The v1.2 result is not a model victory. It is a diagnostic victory.

We learned that:

1. `cyclic_motif_fast_replay` remains unable to create memory in sparse-success MultiRoom.
2. `cyclic_subgoal_ecology_replay` fixes the empty-memory problem.
3. Subgoal memory alone does not create goal-directed navigation.
4. The learned agents still underperform simple wall-following on mobility and room-transition behavior.
5. The next bottleneck is action policy structure, not archive capacity.

The strongest signal is that MultiRoom requires a navigation prior or option-like behavior:

```text
follow wall -> detect doorway / transition -> preserve direction through room -> avoid local revisits
```

The current tabular Q-table can store this if discovered, but the evolutionary schedule is not reliably discovering or preserving it.

## Next Step

Do not add more phases yet.

The next useful upgrade is a navigation diagnostic layer and option extraction:

- detect corridor / doorway-like transitions from trajectories;
- extract wall-follow or doorway-crossing action motifs;
- evaluate whether replaying these motifs increases room transitions before measuring success;
- add a `navigation_motif_count` separate from generic `subgoal_motif_count`.

This keeps the project general: the mechanism is not "hard-code MultiRoom", but "extract reusable transition behavior from failed trajectories."
