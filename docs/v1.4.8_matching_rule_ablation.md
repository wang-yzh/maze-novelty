# v1.4.8 Matching Rule Ablation

## Goal

After `v1.4.7`, the main open question was:

```text
Are reusable priors being blocked by a matching rule that is too strict?
```

The specific suspicion was:

- priors are based on egocentric local structure;
- actions are relative actions (`left`, `right`, `forward`);
- but `StateSignature.matches()` still required exact absolute direction.

This version adds a small A/B:

```text
strict
vs
direction_agnostic
```

No new cycle was added.

## Code Change

Added:

- configurable `StateSignature.matches(..., mode=...)`;
- `BehaviorLibrary.match_mode`;
- `TargetReuseConfig.match_mode`;
- diagnostic runner support for:

  ```text
  --reuse-match-modes strict,direction_agnostic
  ```

The matching mode is encoded into the transfer method label:

```text
...+target_reuse[strict]
...+target_reuse[direction_agnostic]
```

## Quick Smoke

Command:

```bash
uv run python scripts/run_pretraining_transfer_diagnostic.py \
  --seeds 7 \
  --target-envs MiniGrid-MultiRoom-N2-S4-v0,MiniGrid-MultiRoom-N4-S5-v0 \
  --methods operate_replay_pretrain,cyclic_motif_fast_replay_pretrain,cyclic_subgoal_ecology_replay_pretrain \
  --pretrain-episodes 16 \
  --adapt-episodes 12 \
  --eval-every 6 \
  --eval-episodes 2 \
  --include-target-reuse \
  --reuse-match-modes strict,direction_agnostic \
  --output outputs/pretraining_match_ablation_quick.csv \
  --summary-output outputs/pretraining_match_ablation_quick_summary.csv
```

## Primary Result

Final task result remains:

```text
final_score = 0
adaptation_auc = 0
```

So this is not a transfer breakthrough.

But the mechanism-level signal is strong.

## Main Signal

Direction-agnostic matching frequently increases:

- matched prior count;
- executed prior count;
- executed prior steps.

### `MiniGrid-MultiRoom-N2-S4-v0`

| Method | Match Mode | Matched | Executed | Steps |
| --- | --- | ---: | ---: | ---: |
| `operate_replay` | `strict` | `133` | `44` | `264` |
| `operate_replay` | `direction_agnostic` | `154` | `47` | `282` |
| `motif_fast` | `strict` | `111` | `33` | `198` |
| `motif_fast` | `direction_agnostic` | `338` | `110` | `660` |
| `subgoal_ecology` | `strict` | `7` | `3` | `18` |
| `subgoal_ecology` | `direction_agnostic` | `19` | `9` | `54` |

### `MiniGrid-MultiRoom-N4-S5-v0`

| Method | Match Mode | Matched | Executed | Steps |
| --- | --- | ---: | ---: | ---: |
| `operate_replay` | `strict` | `96` | `30` | `153` |
| `operate_replay` | `direction_agnostic` | `317` | `77` | `462` |
| `motif_fast` | `strict` | `204` | `53` | `279` |
| `motif_fast` | `direction_agnostic` | `319` | `92` | `489` |
| `subgoal_ecology` | `strict` | `82` | `27` | `162` |
| `subgoal_ecology` | `direction_agnostic` | `292` | `91` | `489` |

## Interpretation

This is a useful positive result.

It means:

```text
the previous strict matching rule was probably suppressing real reusable priors
```

The strongest quick-smoke gain appears in:

```text
cyclic_motif_fast_replay on N2-S4
111 -> 338 matched
33  -> 110 executed
198 -> 660 executed steps
```

And the clearest broad gain on the harder target appears in:

```text
cyclic_subgoal_ecology on N4-S5
82 -> 292 matched
27 -> 91 executed
162 -> 489 executed steps
```

So the ablation gives the first clear answer to the stage-A question:

```text
yes, matching semantics were part of the bottleneck
```

## Important Limitation

The stronger matching signal did **not** yet create nonzero final transfer.

So the right conclusion is:

```text
better matching helps reusable structure become active,
but activation alone is still not enough for task success
```

That means:

1. the matching rule should likely move toward `direction_agnostic` as the new
   default research setting;
2. the next bottleneck is still execution quality and composition;
3. the next step should remain:

   ```text
   short option execution / better prior execution semantics
   ```

## Decision

Based on this smoke:

```text
direction_agnostic matching should be promoted into the next serious experiment
```

Not because it solves transfer, but because it clearly improves the mechanism we
care about:

```text
reusable prior matching and execution
```

## Next Step

Recommended next run:

  - `operate_replay_pretrain`
