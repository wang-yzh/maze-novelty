# v1.4.15 Prior Lifecycle Diagnostics

## Goal

`v1.4.14` added option-level continuation rules, but the diagnostic output still
mixed several failure modes together.

This step separates prior execution into a small lifecycle:

```text
matched -> started -> first step outcome -> completed | aborted | truncated
```

The purpose is to answer a practical question:

```text
Should we improve prior extraction/matching, or should we improve continuation
rules?
```

## New Metrics

The target-reuse summary now records:

| Metric | Meaning |
| --- | --- |
| `target_reuse_completed_prior_count` | prior finished all selected actions |
| `target_reuse_truncated_prior_count` | episode ended before prior finished |
| `target_reuse_first_step_mismatch_count` | prior was already inconsistent after its first action |
| `target_reuse_first_step_stall_count` | first action was a failed forward movement |
| `target_reuse_mismatch_abort_count` | abort caused by signature mismatch |
| `target_reuse_stall_abort_count` | abort caused by failed forward movement |
| `target_reuse_progress_lost_abort_count` | `progress_guard` aborted because mismatch remained and coarse progress evidence disappeared |

This makes the difference between these two failures visible:

```text
bad launch:
  the first action already contradicts the expected transition

bad continuation:
  the launch was plausible, but the option should have stopped later
```

## Quick Diagnostic Read

### `cyclic_motif_fast_replay`

| Target | Started | Completed | Aborted | Truncated | First-Step Mismatch | First-Step Stall | Mismatch Aborts | Stall Aborts |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| `N2-S4` | `96` | `64` | `30` | `2` | `12` | `16` | `14` | `16` |
| `N4-S5` | `113` | `8` | `103` | `2` | `67` | `17` | `60` | `43` |

Interpretation:

```text
N4-S5 is not mainly a continuation-rule problem.
The prior often starts in a state that immediately disagrees with the first
expected transition.
```

For `motif_fast`, the next likely bottleneck is:

```text
prior initiation / descriptor matching quality
```

not another abort threshold.

### `cyclic_subgoal_ecology_replay`

| Target | Started | Completed | Aborted | Truncated | First-Step Mismatch | Progress-Lost Aborts |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `N2-S4` | `34` | `29` | `3` | `2` | `3` | `3` |
| `N4-S5` | `78` | `41` | `36` | `1` | `21` | `36` |

Interpretation:

```text
ecology priors start more cleanly than motif_fast, but progress_guard still
cuts many options on N4-S5.
```

This suggests the subgoal/ecology line needs a better progress signal, not just
more permissive continuation. The current progress evidence is based on coarse
signature fields; it is useful but blunt.

### `operate_replay`

| Target | Started | Completed | Aborted | Truncated | First-Step Mismatch | First-Step Stall |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `N2-S4` | `67` | `66` | `0` | `1` | `27` | `0` |
| `N4-S5` | `54` | `53` | `0` | `1` | `31` | `10` |

Interpretation:

```text
open-loop replay completes because it does not abort, not because it is clean.
```

This explains why open-loop can recover execution volume while still giving weak
structural transfer.

## Decision

This diagnostic layer should stay.

It changes the next engineering question from:

```text
Which cycle variant is best?
```

to:

```text
Which part of transfer fails first?
```

That is a better fit for pretraining research.

## Next Useful Step

The next code step should target descriptor/matching quality before adding more
cycle phases.

A concrete candidate:

```text
add a room-transition / movement-effect descriptor to priors
```

The goal would be to reduce first-step mismatch for transferred motifs,
especially on `MiniGrid-MultiRoom-N4-S5-v0`.
